# Environment Variables Documentation

## Overview
This document outlines all environment variables required for the Brand Baggy E-commerce application to function properly. The application has two main parts: **Client** (Next.js) and **Server** (Django).

---

## CLIENT ENVIRONMENT VARIABLES
**Location**: `client/.env.local` or `client/.env`

### API Configuration
- **NEXT_PUBLIC_API_URL**
  - Description: Base URL for the Django backend API
  - Example: `http://localhost:8000` (development) or `https://api.example.com` (production)
  - Used in: `lib/axios.tsx`, hooks for API calls
  - Required: Yes

### WebSocket Configuration
- **NEXT_PUBLIC_WS_URL**
  - Description: WebSocket URL for real-time notifications and analytics
  - Example: `ws://localhost:8000` (development) or `wss://api.example.com` (production)
  - Used in: `hooks/useAnalaytics.ts`, `hooks/useNotification.ts`
  - Required: Yes (for real-time features)

### Backend URL (for server-side routes)
- **BACKEND_URL**
  - Description: Backend URL used in API routes (without the /ws prefix)
  - Example: `http://localhost:8000` (development) or `https://api.example.com` (production)
  - Used in: `app/api/paypal/create-order/route.ts`, `app/api/paypal/capture-order/route.ts`
  - Required: Yes (for payment endpoints)

### Payment Gateway - Stripe
- **NEXT_PUBLIC_STRIPE_PUBLIC_KEY**
  - Description: Stripe public key for client-side payment processing
  - Example: `pk_test_51234567890...` (test mode)
  - Used in: `app/payment/components/StripeCheckout.tsx`
  - Required: Yes (for Stripe payments)

### Node Environment
- **NODE_ENV**
  - Description: Environment mode (automatically set by Next.js)
  - Values: `development`, `production`
  - Used in: `lib/axios.tsx` for logging
  - Required: No (auto-managed)

## SERVER ENVIRONMENT VARIABLES
**Location**: `server/.env`

### Django Configuration
- **SECRET_KEY**
  - Description: Django secret key for cryptographic operations
  - Default: `django-insecure-8__#a0r#&cfj-8l8w7eq+_45dl74#u^^3bz0l-!w^%*6+&l$mq` (dev only)
  - Example: `your-long-random-secret-key-here`
  - Required: Yes (should be strong in production)
  - Security: Never commit this value; use a strong random string

- **DEBUG**
  - Description: Enable debug mode
  - Values: `True` or `False`
  - Default: `False`
  - Required: No
  - Note: Set to `False` in production

- **RENDER_EXTERNAL_HOSTNAME**
  - Description: External hostname for Render deployment
  - Example: `brand-baggy.onrender.com`
  - Required: No (only for Render deployments)

### Database Configuration
The database is currently hardcoded in settings but supports DATABASE_URL:

- **DATABASE_URL** (currently not used, but settings support it)
  - Description: PostgreSQL connection string
  - Example: `postgresql://user:password@localhost:5432/dbname`
  - Used in: `Backend/settings.py` (commented out)
  - Required: No (hardcoded locally)

### Redis Configuration (Required for Celery and Channels)
- **REDIS_URL**
  - Description: Redis connection URL for message broker and caching
  - Example: `redis://localhost:6379` (development) or `redis://:password@host:port` (production)
  - Used in: Celery broker/backend, Channel layers, Cache backend
  - Required: Yes (for async tasks and WebSockets)

### Email Configuration
- **EMAIL_HOST**
  - Description: SMTP server for sending emails
  - Default: `smtp.gmail.com`
  - Example: `smtp.gmail.com` (Gmail), `smtp.sendgrid.net` (SendGrid)
  - Required: Yes (for transactional emails)

- **EMAIL_PORT**
  - Description: SMTP port
  - Default: `587`
  - Values: `587` (TLS) or `465` (SSL)
  - Required: No

- **EMAIL_HOST_USER**
  - Description: Email account username/address
  - Example: `your_email@gmail.com`
  - Required: Yes (for sending emails)

- **EMAIL_HOST_PASSWORD**
  - Description: Email account password or app password
  - Example: `your_app_password_here`
  - Required: Yes (for sending emails)
  - Security: Use app-specific passwords, not the account password

### Cloudinary Configuration (Image Storage)
- **CLOUDINARY_CLOUD_NAME**
  - Description: Cloudinary cloud name
  - Example: `your-cloud-name`
  - Required: Yes (for image uploads)

- **CLOUDINARY_API_KEY**
  - Description: Cloudinary API key
  - Example: `123456789012345`
  - Required: Yes (for image uploads)

- **CLOUDINARY_API_SECRET**
  - Description: Cloudinary API secret
  - Example: `your-api-secret-here`
  - Required: Yes (for image uploads)
  - Security: Keep this secret

### Payment Gateway - Stripe
- **STRIPE_SECRET_KEY**
  - Description: Stripe secret key for server-side payment processing
  - Example: `sk_test_51234567890...` (test mode)
  - Required: Yes (for Stripe payments)
  - Security: Keep this secret; never expose to client

- **STRIPE_WEBHOOK_SECRET**
  - Description: Stripe webhook signing secret
  - Example: `whsec_test_1234567890...`
  - Required: Yes (for webhook validation)

### Payment Gateway - PayPal
- **PAYPAL_CLIENT_ID**
  - Description: PayPal application client ID
  - Example: `AbCdEfGhIjKlMnOpQrStUvWxYz...`
  - Required: Yes (for PayPal payments)

- **PAYPAL_CLIENT_SECRET**
  - Description: PayPal application secret
  - Example: `EFGhijklmnopqrstuvwxyz...`
  - Required: Yes (for PayPal payments)
  - Security: Keep this secret

- **PAYPALWEBHOOK_ID**
  - Description: PayPal webhook ID for receiving payment notifications
  - Example: `WH-1234567890...`
  - Required: Yes (for PayPal webhook validation)

- **PAYPAL_API_BASE**
  - Description: PayPal API base URL
  - Default: `https://api-m.sandbox.paypal.com`
  - Values: 
    - `https://api-m.sandbox.paypal.com` (sandbox/testing)
    - `https://api-m.paypal.com` (production)
  - Required: No

### Frontend URL (for email links)
- **FRONT_END_URL**
  - Description: Frontend application URL for generating links in emails
  - Default: `http://localhost:3000`
  - Example: `https://brand-baggy.vercel.app` (production)
  - Used in: `orders/tasks.py` for review links
  - Required: No

## SETUP INSTRUCTIONS

### Development Setup

#### Client (.env.local)
```
NEXT_PUBLIC_API_URL=http://localhost:8000
NEXT_PUBLIC_WS_URL=ws://localhost:8000
BACKEND_URL=http://localhost:8000
NEXT_PUBLIC_STRIPE_PUBLIC_KEY=pk_test_your_key_here
```

#### Server (.env)
```
# Django
SECRET_KEY=your-super-secret-key-change-this
DEBUG=True
RENDER_EXTERNAL_HOSTNAME=

# Redis (required)
REDIS_URL=redis://localhost:6379

# Email
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_HOST_USER=your_email@gmail.com
EMAIL_HOST_PASSWORD=your_app_password

# Cloudinary
CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret

# Stripe
STRIPE_SECRET_KEY=sk_test_your_secret_key
STRIPE_WEBHOOK_SECRET=whsec_test_your_secret

# PayPal
PAYPAL_CLIENT_ID=your_client_id
PAYPAL_CLIENT_SECRET=your_client_secret
PAYPALWEBHOOK_ID=your_webhook_id
PAYPAL_API_BASE=https://api-m.sandbox.paypal.com

# Frontend
FRONT_END_URL=http://localhost:3000
```

### Production Setup

#### Client (.env.production)
```
NEXT_PUBLIC_API_URL=https://api.yourdomain.com
NEXT_PUBLIC_WS_URL=wss://api.yourdomain.com
BACKEND_URL=https://api.yourdomain.com
NEXT_PUBLIC_STRIPE_PUBLIC_KEY=pk_live_your_key_here
```

#### Server (.env for production)
```
# Django

DEBUG=False
RENDER_EXTERNAL_HOSTNAME=your-app.onrender.com

# Redis (use managed service)
REDIS_URL=redis://:password@redis-host:6379

# Email (use production email service)
EMAIL_HOST=smtp.sendgrid.net
EMAIL_PORT=587
EMAIL_HOST_USER=apikey
EMAIL_HOST_PASSWORD=your_sendgrid_key

# Cloudinary
CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret

# Stripe (use live keys)
STRIPE_SECRET_KEY=sk_live_your_secret_key
STRIPE_WEBHOOK_SECRET=whsec_live_your_secret

# PayPal (use live credentials)
PAYPAL_CLIENT_ID=your_live_client_id
PAYPAL_CLIENT_SECRET=your_live_client_secret
PAYPALWEBHOOK_ID=your_live_webhook_id
PAYPAL_API_BASE=https://api-m.paypal.com

# Frontend
FRONT_END_URL=https://yourdomain.com
```

## OBTAINING CREDENTIALS

### Stripe
1. Go to https://dashboard.stripe.com
2. Navigate to Developers → API Keys
3. Copy the Publishable Key (for client) and Secret Key (for server)
4. Set up webhooks at Developers → Webhooks

### PayPal
1. Go to https://developer.paypal.com/dashboard
2. Create an app or use the default
3. Copy Client ID and Secret from App Settings
4. Set up webhooks in your PayPal account

### Cloudinary
1. Go to https://cloudinary.com
2. Sign up or log in
3. Navigate to Dashboard
4. Copy Cloud Name, API Key, and API Secret

### Gmail / Email
1. Use an app-specific password (not your account password)
2. For Gmail: https://support.google.com/accounts/answer/185833

### Redis
For production, use a managed service like:
- Render (Redis)
- Upstash
- AWS ElastiCache
- Heroku Redis

## IMPORTANT SECURITY NOTES

⚠️ **Never commit `.env` files to version control**
- Add to `.gitignore`: `.env`, `.env.local`, `.env.*.local`

⚠️ **Use different credentials for each environment**
- Development keys/sandbox mode
- Staging keys/sandbox mode  
- Production keys/live mode

⚠️ **Rotate secrets regularly**
- Change SECRET_KEY if exposed
- Regenerate API keys periodically
- Update webhook secrets after rotation

⚠️ **Use environment-specific values**
- Never use production keys in development
- Never use test keys in production

⚠️ **Store secrets securely in production**
- Use environment variable management services
- Never hardcode secrets in code
- Use secrets management for deployment platforms (Render, Vercel, etc.)

## TROUBLESHOOTING

**"NEXT_PUBLIC_API_URL is undefined"**
- Check `.env.local` exists in the `client/` directory
- Verify the URL is correct
- Next.js requires `NEXT_PUBLIC_` prefix for client-side env vars

**"Redis connection refused"**
- Ensure Redis is running: `redis-cli ping` should return "PONG"
- Check REDIS_URL is correct
- For development: Start Redis with `redis-server`

**"Email not sending"**
- Verify EMAIL_HOST_USER and EMAIL_HOST_PASSWORD are correct
- For Gmail: Enable "Less secure app access" or use app passwords
- Check EMAIL_PORT matches your SMTP provider

**"WebSocket connection failed"**
- Verify NEXT_PUBLIC_WS_URL is accessible
- Ensure it uses `ws://` (dev) or `wss://` (production with SSL)
- Check Django Channels is running and configured

**"Payment processing fails"**
- Verify API keys are for the correct mode (test/live)
- Check webhook endpoints are configured
- For local testing: Use Stripe/PayPal test credentials
